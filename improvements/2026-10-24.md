# 2026-10-24: roadmap item PL-01, the date-night planner is now switched on

## What was done

The date-night planner (pick a day, a time window and a budget, get two or three evening plans with drive times, and save the ones you like) had been built earlier but was never connected to the running app, so nothing in it could be reached. Today it was connected, every part of it was checked with new tests, and it is now written up in the API notes.

## What behaves differently

- The planner's requests (suggest plans, save a plan, list, open, edit, delete) now answer instead of "not found" once this is merged and deployed.
- Nothing you see in the app changes yet: there is still no Plan page. That is the next item (`PL-02`).

## What was tested

- 25 new checks cover: suggesting plans from home or a given start point, walking versus driving, evenings that run past midnight, saving a plan (stops sorted by arrival, title made from the stops, bad input refused), listing upcoming plans before past ones, editing only what is sent, refusing to blank out the title or day, deleting, and missing plans.
- Driving times come from a stand-in, so no map server is needed. The full backend suite passes (314 tests, 289 before).
- Not tried against the live database; the checks use a stand-in for it.

## Still open

- Each saved plan carries a "calendar file" link that does not work yet. Added as `PL-08`, to be done with the calendar export (`PL-05`).
- The Plan page (`PL-02`) is now unblocked and moved to the top of the list.

## Roadmap changes

- `PL-01` done (all three sub tasks), moved to Done.
- `PL-02` moved from Backlog to Now (its dependency is done).
- New `PL-08` for the calendar link that points nowhere.
