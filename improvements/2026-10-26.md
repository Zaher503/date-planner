# 2026-10-26: Footer address for every event on a listing page (IM-01, first part)

**What was done:** the first step of roadmap item IM-01. On 2026-10-17 the Hollywood Roosevelt events page showed shows with no street address and the wrong venue name, because the address and phone live only in the page footer and never reached the events.

## What behaves differently

- When a page is read as text, its footer (address, phone, hotel or venue name) is now passed along with the page, clearly labelled as belonging to the whole site.
- The extraction instructions now say: for a venue page that lists several events, use that venue as the place and that address for every event that gives no address of its own.

## Tested

- Backend tests: 294 passed, including two new ones (footer is attached and labelled; the instructions mention it).
- Not tested against the live link: this was a roadmap day, so no live import was run. Whether the model really picks up the footer must be checked after this is deployed.

## Still open

- Rerun the Hollywood Roosevelt link after deploy (sub task IM-01.2). If the model still ignores the footer, copy a single footer address onto events that have none.
- Pages that carry their events in structured data do not get the footer yet.
