# 2026-11-03: roadmap item `DS-01`, calendar feeds can now be added

Today was a roadmap day (yesterday was an import check).

## What was done
The app can now read public calendar feeds (city, library, park and venue calendars, the kind that end in `.ics`). Before today the reader existed but was switched off: nothing knew about it and there was no way to give it a feed.

## What behaves differently
- The feed reader is now part of the list of event sources, so the discovery dry run includes it.
- You can save the list of feeds with a new call (`GET` / `PUT /api/discover/feeds`, written up in `docs/API.md`). There is no screen for it yet; that is `DS-10`.
- With no feeds saved the source is simply skipped ("nothing configured"), not an error.
- Repeating events (every Wednesday, with a skipped week) become one event per date, cancelled events are marked, and events outside the area or the time window are dropped.
- A feed that is broken is skipped and the others still load; the run only fails if every feed is broken.
- Found on the way: the two libraries the reader needs were not in the install list, so a fresh deploy of the server would have crashed on them as soon as the reader was used. They are added.

## Tested
7 new tests using the saved sample calendar (repeats, a skipped week, all-day, cancelled, far-away and past events, `webcal://` links, one broken feed, saving and reading back the list, bad links rejected). All 398 backend tests pass. No screenshot: nothing changes in what the app shows.

## Still open
- No screen to add feeds (`DS-10`) and nothing runs discovery on a schedule or saves what it finds (`DS-03`, `DS-04`). Until then the feeds can only be tried with the dry run.
- Not tried against a real live calendar yet; suggestion: add one real public feed (for example a city calendar) when the Settings screen exists.
